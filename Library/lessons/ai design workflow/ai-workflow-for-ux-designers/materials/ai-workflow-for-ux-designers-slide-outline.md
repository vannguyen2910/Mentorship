### DIAGRAM · Context and the context window
- Kicker: Group 2, talking to the AI
- Title: Everything it can see\nis *context*
- On-slide: Context window: the limit on how much it can hold at once
- Speaker notes:
  - Context is your instruction, pasted text, attached files and earlier messages; nothing else about your project

### STATEMENT · Hallucination
- Kicker: Group 3, when it goes wrong
- Title: Confident,\nand *invented.*
- On-slide: Let it say "unknown".
- Speaker notes:
  - Examples: a competitor that does not exist, a quote nobody said

### DIAGRAM · An agent takes many steps

- Title: One request,\n*many steps*
- On-slide: Check the files it changed, not only the reply.

  - AI coding tools often work this way
  - So the reply is a summary; the truth is in the folder
  - Connector (MCP): a way to let a tool read another app, such as a design file; know what it can see and change first

### NUMBERED · Three kinds of material
- Kicker: What you put in
- Title: Before you paste,\n*sort it*
- On-slide:
  - Safe: public facts, your own thinking, the course case
  - Ask first: internal, not sensitive; approved tool only
  - Never in a public tool: personal data, unreleased plans, finances, NDA material
- Speaker notes:
  - Everything so far was about what comes out; this is about what goes in
  - **Do not assume it is private**: on many consumer plans conversations may be used to improve the model unless you turn it off; check the tool you use
  - Personal data in Vietnam is covered by the 2025 law in force from 1 January 2026; names, emails and recordings count; this is not legal advice
  - Run the six-card sorting exercise in pairs (three minutes), then discuss disagreements
  - Expected: public pricing page and notes on a public app are safe; the rest are never in a public tool (anonymise first where possible)
- 🎨 Visual hint: TYPOGRAPHIC. Numbered, three columns with a one-line example under each; no colour coding beyond purple numerals.

### PROCESS · Before you paste
- Kicker: Four habits
- Title: Check, sort,\n*clean, contain*
- On-slide:
  - 01 · Check your company's AI policy
  - 02 · Sort the material
  - 03 · Remove names and identifiers first
  - 04 · Keep confidential files out of the tool's folder
- Speaker notes:
  - If there is no policy, ask; when in doubt, do not paste
  - **Remove identifiers with find and replace on your own computer**, not by asking the AI, because that already sends the data
  - An AI coding tool or agent reads the whole project folder, so keep private files elsewhere
  - Whether AI output can be used in client work, and who owns it, depends on your company and country; say where AI was used in the case log
  - Output: three lines in `data-rules.md`, finished in Activity 2
- 🎨 Visual hint: SCHEMATIC. Four-step process track, step three highlighted in purple.

### COMPARE · Markdown or HTML?
- Kicker: Two file types
- Title: One to work in.\n*One to show.*
- On-slide:
  - Left, Markdown (.md): plain text with simple marks; what AI reads and writes best
  - Right, HTML: what a browser draws; prototypes and the hub are HTML
- Speaker notes:
  - Markdown: `##` for headings, `**` for bold, `-` for lists, `|` for tables
  - You only need to recognise it and know you can paste it back into an AI chat
  - You keep the Markdown; the AI builds the page when a stakeholder needs to read it
  - Naming HTML tags makes feedback usable: "the button is outside the card container" beats "this looks off"
- 🎨 Visual hint: SCHEMATIC. Two-column compare. Left shows a few lines of Markdown, right shows the same text as a rendered page card, with a small arrow labelled "AI" between them.

---

### DIAGRAM · The case folder
- Kicker: One plain local folder
- Title: Every lesson points\nto *this folder*
- On-slide: 00-context · 01-discover · 02-define · 03-develop · 04-deliver · hub · case-log
- Speaker notes:
  - A local folder is on your own computer, not a design file on a server or a cloud document
  - An AI coding tool opens the whole folder as its project and reads everything inside; cloud-sync folders can misbehave mid-write
  - Walk the tree: the context pack first, then one folder per stage
  - Numbered folders stay in order; one file per activity gives each AI step a named input
  - Other layouts are fine for your own projects; here we use this one
- 🎨 Visual hint: SCHEMATIC. A clean folder tree with the context folder highlighted in purple and the hub folder in ink.

### PROCESS · One working file, section by section
- Kicker: Keep it safe
- Title: One file.\n*Filled step by step.*
- On-slide:
  - 01 · Give the AI only the sections it needs
  - 02 · It returns only its own section
  - 03 · You paste it in and check it
  - 04 · Keep the AI draft and your checked version apart
- Speaker notes:
  - Each activity in the series fills one Markdown file, a section per step

  - Keeping the draft and your version separate shows your error rate
