Section 6

Simulate One
"Oops"

Break something small on purpose, then fix it for real.

Recovery, one clean way

Two ways
to undo.

Uncommitted file
Right-click in Changes → Discard Changes
Use this when the mistake hasn't been committed yet — it just erases the edit.
Already-committed change
Right-click in History → Amend Commit → fix the file → re-commit
Use this when the mistake is already committed — it fixes and replaces that commit.
The same recovery, as an outcome

to fix it.

The loop you'll repeat

Pull. Branch. Commit.
Push. Pull request. Pull.

1
Pull
Fetch origin, then Pull — every time you sit down.
2
Branch
New branch per change, e.g. tokens/update-spacing. Never work on main.
3
Commit
One clear message about what changed and why.
4
Push the branch
Publish branch — your work goes up, main stays untouched.
5
Pull request
Describe the change; a teammate reviews and merges.
6
Pull again
Get the merged result, then start the next branch.

visibilityCheck before it pushes. Open the changes in GitHub Desktop — AI tools sometimes edit more files than you asked for.
The team's one-page SOP

The working agreement
ships with the repo.

CONTRIBUTING.md
  • Never commit to main — one branch per change
  • Pull before you start each session
  • Branch names: area/short-description
  • Commit messages say what changed and why
Pull requests & safety
  • Every PR: summary, screenshot if the UI changed, tokens or components touched
  • One reviewer approves; the owner merges
  • Clash on a shared file? Stop and ask who owns it
  • Public repo: no keys, no .env, ever
